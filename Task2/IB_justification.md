# Обоснование выделения разделов/вопросов для аудита IB

## I. Управление доступом

Раздел сфокусирован на контроле доступа между партнёрами и клиентами — ключевая проблема бизнеса. Оставлены вопросы, закрывающие бесконтрольный доступ к данным и внешние интеграции.

| № | Вопрос | Обоснование |
|---|--------|-------------|
| 1 | Используется ли многофакторная аутентификация (MFA) для доступа к критическим системам и сервисам? | Прямое отношение к контролю доступа и защите от утечек |
| 2 | Проводится ли аудит и пересмотр учётных записей с повышенными привилегиями на регулярной основе? | Разграничение доступа между партнёрами — ключевая проблема |
| 3 | Реализован ли принцип минимальных привилегий при назначении ролей и прав доступа? | Прямое отношение: партнёры получают данные, к которым не должны иметь доступ |
| 4 | Ведётся ли журналирование всех операций доступа к системам и данным? Кто имеет доступ к журналам? | Необходим для расследования утечек и аудита |
| 5 | Используются ли механизмы контроля доступа на основе атрибутов для повышения гибкости управления доступом? | Релевантен для тонкого разграничения между партнёрами |
| 6 | Используются ли системы аутентификации пользователей для доступа к системам? | База для контроля доступа |
| 7 | Ограничен ли доступ к системам из внешних источников? | Критично: API партнёров — внешние источники |
| 8 | Ведётся ли единый реестр учётных записей? | Базовый механизм контроля доступа |
| 9 | Используются ли средства управления учётными записями на базе единого реестра? | Базовый механизм контроля доступа |
| 10 | Применяются ли средства для отзыва прав доступа? | Базовый механизм контроля доступа |
| 11 | Используются ли средства централизованного контроля доступа? | Закрывает проблему бесконтрольного доступа |

## II. Безопасность данных

Раздел сфокусирован на Data Governance, классификации данных и compliance (152-ФЗ). Именно здесь лежат проблемы утечек ПД через API и блокировка BI/ML/AI из-за хаоса в управлении данными.

| № | Вопрос | Обоснование |
|---|--------|-------------|
| 1 | Разработана ли политика классификации данных, и актуализируется ли она в соответствии с действующим законодательством? | Основа для compliance и Data Governance. Без классификации невозможно контролировать потоки |
| 2 | Ведётся ли учёт персональных данных, и применяются ли специальные процедуры обработки и хранения для различных типов данных? | Ключевой вопрос для 152-ФЗ и жалоб клиентов |
| 3 | Осуществляется ли мониторинг доступа к данным на основе их классификации? Используются ли метки безопасности для маркировки данных? | Позволяет выявить, кто и к каким данным обращается — решает проблему «чужих данных» |
| 4 | Разработаны ли процессы и системы Data Governance для управления данными? | Критичен для BI/ML/AI — без Data Governance нельзя строить новые сервисы на данных |
| 5 | Применяются ли средства или процессы анонимизации данных? | Релевантно для ML/AI-сервисов и compliance |
| 6 | Разработана ли инструкция по процессу восстановления данных? | Compliance |

## III. Защита инфраструктуры

Раздел сокращён до базового обнаружения атак и фильтрации. Инфраструктурные проблемы не являются первоочередными — утечки идут на прикладном уровне (API, БД).

| № | Вопрос | Обоснование |
|---|--------|-------------|
| 1 | Используется ли межсетевой экран для ограничения входящего и исходящего трафика? | Базовая защита периметра |
| 2 | Используются ли IDS/IPS-системы для обнаружения и предотвращения сетевых атак? | Обнаружение атак — часть предотвращения инцидентов |
| 3 | Проводится ли регулярное сканирование уязвимостей операционных систем, приложений и сетевых устройств? | Находит проблемы в API и конфигурациях доступа |
| 4 | Осуществляется ли фильтрация трафика между сетевыми сегментами? | Релевантно для изоляции потоков данных |

## IV. Управление инцидентами

Раздел сфокусирован на обнаружении, реакции и аудите — ключевые потребности после инцидента у конкурента и для compliance.

| № | Вопрос | Обоснование |
|---|--------|-------------|
| 1 | Используется ли система мониторинга безопасности (SIEM) для корреляции событий и анализа аномалий в режиме реального времени? | Корреляция событий для выявления утечек |
| 2 | Настроены ли автоматические оповещения об инцидентах и подозрительной активности? | Скорость реакции на инциденты |
| 3 | Разработан ли план реагирования на инциденты, включающий анализ, эскалацию и восстановление системы? | Критичен после инцидента у конкурента |
| 4 | Ведётся ли статистика по всем зарегистрированным инцидентам и используются ли результаты анализа для корректировки политики безопасности? | Анализ для корректировки политик безопасности |
| 5  | Как часто проводятся внутренние и внешние аудиты безопасности? Обновляются ли политики на основе результатов аудитов? | Ключевой запрос бизнеса — провести аудит |
